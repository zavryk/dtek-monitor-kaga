# DTEK power outages monitor — Київська область (КРЕМ)

Київ обслуговує окремий репозиторій: у нього інший домен і інша форма
запиту (див. таблицю нижче). Код тут підтримує обидва провайдери, тож
київський може взяти його як є й змінити лише `config.json`.

Стежить за **аварійними (екстреними)** відключеннями на сторінці ДТЕК і
пише в Telegram, коли для конкретної адреси з'являється новий період.

Планові відключення тут не обробляються навмисно: для них є графік, і
його показує окремий бот на дошках.

## Як це влаштовано

Сайти ДТЕК стоять за Imperva, і звичайний HTTP-запит отримує 212 байт
JS-заглушки замість сторінки. Тому дані бере справжній Chromium
(Playwright): відкриває сторінку, забирає `csrf-token` і виконує
`POST /ua/ajax` **всередині сторінки**, з її куками.

Два обленерго — два домени й дві різні форми запиту:

| Провайдер | Домен | Питає |
|---|---|---|
| `krem` | `dtek-krem.com.ua` | місто **і** вулицю |
| `kem`  | `dtek-kem.com.ua`  | лише вулицю |

## Конфігурація

Адреси — не секрет, тому лежать у `config.json`:

```json
{
  "targets": [
    {
      "id": "kaga-molodizhna",
      "provider": "krem",
      "city": "м. Кагарлик",
      "street": "вул. Молодіжна",
      "house": "14А",
      "chats": [
        { "chat_id": "-1002085477927" },
        { "chat_id": "-1002476122936", "thread_id": 5474 }
      ]
    }
  ]
}
```

Один прогін обходить усі адреси одним браузером. Додати адресу — це
рядок у конфігу, а не ще один репозиторій і ще один таймер.

У секретах лишається тільки те, що справді секрет:

| Секрет | Навіщо |
|---|---|
| `TELEGRAM_BOT_TOKEN` | від імені кого писати |
| `TELEGRAM_ALERT_CHAT_ID` | куди скаржитись на поломки монітора |
| `PAT` | щоб workflow міг закомітити стан |

## Стан

`artifacts/state.json`, ключ — `id` цілі:

```json
{
  "kaga-molodizhna": {
    "period": "06:46 18.08.2026 — 23:35 18.08.2026",
    "updated_at": "2026-08-18T17:07:34.208Z",
    "fail_streak": 0,
    "failing_since": null
  }
}
```

Ключ саме `id`, а не адреса рядком: адресу можна виправити (кома,
скорочення, `14А` → `14-А`), і стан не має від цього губитися.

## Що робиться зі збоями

Три різні речі, які раніше зливались в одну:

1. **Будинку немає у відповіді.** Стара версія читала це як «є
   відключення» (`undefined !== ""`), потім падала на
   `undefined.toLowerCase()` — і мовчки, бо помилка не доходила до коду
   виходу. Тепер це окремий стан: адреса в конфігу розійшлася з
   довідником ДТЕК, і про це видно одразу.
2. **Прогін падає** — процес виходить кодом 1, прогін у Actions стає
   червоним, GitHub шле листа. Раніше `run().catch(console.error)`
   ковтав будь-яку помилку, і зламаний монітор виглядав здоровим.
3. **Скарга в Telegram — на зміну стану, а не на спробу.** Одна невдача
   це мережа; `FAIL_ALERT_AFTER` поспіль (типово 3, тобто пів години) —
   це поломка, і про неї приходить одне повідомлення. Коли дані
   повертаються — одне про відновлення, з тривалістю простою.

Чого тут навмисно немає: сторожа на «сайт не оновлює `updateTimestamp`».
Я не знаю, чи ДТЕК оновлює цю мітку в спокійні періоди, а сторож на
сигналі з невідомою семантикою давав би або хибні тривоги, або хибний
спокій.

## Локально

```bash
npm ci
npx playwright install chromium
node --env-file=.env ./src/monitor.js
```

`.env` — за зразком `.env.example`.
